## Release Evidence Infrastructure (2026-07-31)

The following tools produce and consume structured release evidence for gates 6-11:

- **`Scripts/device-test.sh`** — Enhanced with `--layer lifecycle|offline|qa-full`,
  `--evidence-dir PATH`. Records machine facts (device, OS, build revision,
  catalog version, exact commands, individual named-suite outcomes, xcresult
  hashes, and screenshot hashes) into `evidence.json`. Prompts operator
  observations for scenarios XCTest cannot prove.

- **`Scripts/release-gate-check.sh`** — Consumes evidence from all workstreams
  to produce a single `READY` / `NOT_READY` verdict and a structured
  `gate-checklist.md` with specific blockers.

- **`docs/release-evidence/`** — Evidence directory tree:
  - `gate-checklist.md` — auto-generated by gate checker
  - `final-verdict.md` — auto-generated by gate checker
  - `catalog-verification.json` — generated only by a fully successful
    `verify-model-catalog.py --evidence` run; failed/partial attempts use explicit
    attempt filenames and cannot pass Gate 2
  - `lifecycle/` — Issue 06 evidence (device-test.sh --layer lifecycle)
  - `offline/` — Issue 07 evidence (device-test.sh --layer offline)
  - `physical-qa/` — Issue 08 evidence (device-test.sh --layer qa-full)

- **`docs/qa-failure-map.md`** — Every failed physical scenario must link to a
  focused ticket URL. PENDING rows without URLs are blocking.

- **`docs/release-gates.md`** — Updated with 11 gates (was 7). Removed stale
  "missing Llama SHA-256" claim — the current catalog contains digests at
  `AIModel.swift:207` and metadata validation passes.
